# Decision records

How to read these records, mirroring the product specification's "What this
specification binds": a decision binds functional responsibilities, outcomes,
and authored project formats. The authored folder is the portable convention,
so its filenames and schemas are exact contract, as is anything a record
explicitly marks exact — a native server name, a published canonical path, a
distribution artifact name.

Command names, flags, generated-file mechanics, and internal state shown in a
record are the reference rendering of its responsibilities, not the contract:
a conforming implementation may render them differently provided every
responsibility, boundary, and safety property holds and machine-facing
outputs stay stable and parseable.
